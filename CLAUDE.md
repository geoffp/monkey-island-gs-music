# CLAUDE.md

Guidance for Claude Code working in this repository.

## Goal
Extract the Roland MT-32 soundtrack of *The Secret of Monkey Island* (DOS VGA floppy, SCUMM v4) and port it to the Apple IIGS as **NinjaTrackerPlus** songs: the MT-32 sampled through Munt, played by the Ensoniq DOC. MIDI Synth (System 6 / synthLAB) sequences are an **experimental aside**, kept working but not the target.

Pipeline:
1. **Docs** (`docs/`): record format knowledge and sources before writing code that depends on it.
2. **Extract** (`src/migs/extract_music.py` → `build/music/`): MT-32 `RO` tracks → Standard MIDI Files in **two renditions from one parse**:
   - `build/music/midi/mt32/`: faithful;
   - `build/music/midi/gm/`: converted per `docs/mt32-to-gm.md`;
   - plus per-song patch notes (`build/music/patches/*.toml`).

   Keep both renditions working. Test the MT-32 one with Munt (`just mt32-wav`, user-supplied ROMs in `original files/mt-32 roms/`) and the GM one with FluidSynth + GeneralUser GS (`just gm-wav`).
3. **NinjaTrackerPlus** (`src/migs/ntpmod.py` build CLI: samples in `ntpsamples.py`, arrangement in `ntpsong.py`, MOD writer in `modfile.py`; `config/ntp.toml` → `build/ntp/`): MT-32 SMF → ProTracker MOD within NinjaTrackerPlus limits (31 oscillators, 64 KB DOC RAM, no streaming) → `.NTP` via Ninjaforce's PHP converter (`just ntp`). The MOD is the primary artefact: preview it on the desktop (`just ntpmod`) before going to the IIGS. Sample construction research (attack detection, loop candidates, metrics): `just looplab` → `build/looplab/`, findings in `docs/loop-detection.md`.
4. **MIDI Synth (experimental aside)** (`src/migs/` → `build/seq/`): SMF → MIDI Synth sequence ($D5/aux 1), with channels mapped to instrument slots.

## Key facts (verified against the data; details in docs/)
- Game data lives in `original files/The Secret of Monkey Island (Floppy DOS VGA)/`. ScummVM md5 `15e03ffbfeddb9c2aebc13dcb2a4a8f4` = monkey VGA, EN, DOS. **Read-only. Never commit it** (it is gitignored; `original files/README.md` lists what goes there).
- `000.LFL` index is **not** encrypted. `DISKnn.LEC` are XOR 0x69.
- v4 blocks are `uint32 LE size (includes 6-byte header)` + 2-char tag.
- The MT-32 music is **sounds 150–168, all in room 94 on DISK04.LEC**, stored as top-level `RO` blocks in that room's `LF`. The tag clashes with the room block `RO`. Sound offset from index `0N` is relative to the LF data start (LF offset + 8).
- Ordinary `SO` sound blocks hold only `WA` (PC speaker) and `AD` (AdLib) data. They are not the MT-32 source.
- `RO` stream format: see `docs/ro-format.md`. Reference parser: `ref/scummvm/engines/scumm/midiparser_ro.cpp`.
- The CD release (SCUMM v5) has no soundtrack MIDI (its music is Redbook audio). Don't use it as a music source.

## Reference code
`ref/scummvm` is a shallow git submodule. Most useful files:
- `engines/scumm/midiparser_ro.cpp`: `RO` event grammar
- `engines/scumm/sound.cpp`: `readSoundResourceSmallHeader` (v4 WA/AD/RO selection)
- `engines/scumm/resource_v4.cpp`: v4 index/directory reading, DISK09 Roland-patch workaround (EGA)
- `engines/scumm/imuse/`: iMUSE (MT-32 handling, SysEx)
- `engines/scumm/scumm-md5.h`: release identification

## IIGS emulator
- Emulator: GSSquared AppImage at `vendor/gssquared/GSSquared-x86_64.AppImage` (`just fetch-gssquared`).
  - **`just emu`** boots the **NinjaTrackerPlus disk**, a BazFast hard-disk image (`build/disks/MI.NTP.PO`, from `just disk`, sized to the smallest power of two that holds it, at most 32 MB; 4 MB now), straight into SenseiPlay with our songs in `/songs`. BazFast (`bazfast3`, slot 7) is GSSquared's SmartPort card with zero-cycle "Super DMA" transfers, much faster than the 800K floppies (removed 2026-11-07).
  - **Experimental aside:** `just emu-synthlab` boots `build/disks/MI.SYNTHLAB.PO` (`just synthlab-disk`, volume `/MI.SYNTHLAB`, sized the same way: 8 MB now). It merges System 6.0.4 (boot disk + SystemTools1 Finder/CDevs/DAs/FSTs/tools/fonts + SystemTools3), Tool035, `/synthLAB` with our `Seq.and.Instr`, and SenseiPlay with the NTP songs too (verified 2026-11-06 as `MI.HD.PO`).
  - **Machine configs** are generated by `gs2-config` (`migs.emu`) into `build/disks/<name>.gs2`. They keep the `id` and battery RAM that GSSquared writes back on quit, and patch battery RAM: Startup Slot (7 for HD, 5 for floppies), Slot 6 = "Your Card" (no 5.25" drives), and Slot 7 = "Your Card" for BazFast.
  - New configs are seeded from `config/emu/default-bram.hex`, a ROM-accepted image.
  - The battery-RAM checksum is ROM `BCheckSum`. The carry into each `ROL` is always 0 because `CPX #$FF` clears it (verified against saved battery RAM). Map: GSSquared `Docs/GSClockBatteryRAM.md`.
  - Host speed defaults to `ludicrous`; pass e.g. `just emu 2.8mhz`. Config format: GSSquared `Docs/SystemConfigTOML.md`; storage and BazFast: `Docs/Storage.md`.
- System 6.0.4 (an unofficial community GS/OS release, not redistributable here) is fetched by `just fetch-system6` into `vendor/system6/` (Asimov archive, sha256-pinned): System.Disk, SystemTools1/3 and synthLAB, for the synthLAB disk and `stock-banks`.
- Disk images and ShrinkIt archives: CiderPress II CLI at `vendor/cp2/cp2` (`just fetch-cp2`).

## Conventions
- **Cross-platform.** We value builds that work on other people's machines. Linux is the base: everything must work there. macOS is a goal: keep it working. The BSDs (FreeBSD first) are a stretch goal: don't break them needlessly, and accept that the emulator recipes may not run there. Windows is a maybe-someday. In practice:
  - write recipes for POSIX tools, not GNU-only flags (no `nproc`, `stat -c`, `sed -i`, `xargs -d`, `sha256sum`; use `num_cpus()`, `wc -c`, `tools/fresh.py`);
  - expect bash 3.2 (macOS);
  - choose downloads by `os()`/`arch()`, and when a tool has no build for a platform, say so and carry on rather than fail;
  - `just selftest` checks a clean-clone build (with your game data); `just smoke` checks the fetched tools run; CI (`.github/workflows/build.yml`) runs setup, tests and smoke on Ubuntu, macOS and FreeBSD (allowed to fail), weekly too, to catch downloads that break.
- Tasks: `justfile` (run `just` to list). Key recipes:
  - `just test`: unit tests;
  - `just extract`: MT-32 + GM MIDI and patch notes into `build/music/`;
  - `just render`: WAVs through Munt and FluidSynth;
  - `just ntp`: MODs and `.NTP` songs for every build variant in `build/ntp/` (`just ntpmod` stops at the MODs and desktop previews);
  - `just disk`: the NinjaTrackerPlus disk `build/disks/MI.NTP.PO`;
  - `just emu`: boot it in GSSquared.
  - Experimental aside (MIDI Synth): `just seq` (sequences in `build/seq/`), `just mt32bank` (sample the MT-32 through Munt into the shared MI1 bank, spec `config/mt32bank.toml`), `just synthlab-disk` (`build/disks/MI.SYNTHLAB.PO`), `just emu-synthlab`.
- Export profiles (`[profiles]` in `config/instruments.toml`): `stock` (COMBO, from the GM MIDI) and `mt32` (MI1, from the MT-32 MIDI). Each goes to `build/seq/<profile>/` and `/synthLAB/<Folder>` on the HD. **Keep one shared bank** for MIDI Synth: a game port can't load banks between songs. NinjaTrackerPlus is different: each `.NTP` carries its own samples, and `NTPprepare` loads them per song. So NTP builds **both** sample-set modes (`per-song`, `shared`) side by side, as the variants `inst-per-song` and `inst-shared` (`[modes.<name>]` with a `base` in `config/ntp.toml`; output in `build/ntp/inst-per-song/`, `build/ntp/inst-shared/`), plus any trial variants, all listed in the justfile's `ntp_modes`. The disks have one folder per variant (`INST.PER.SONG`, `INST.SHARED`; ProDOS names: 15 characters, no `-`). Short loops are E′+ (`loop_construction = "eprime"`, code in `src/migs/loopbuild.py`); the original averaged loops stay available as `"averaged"`.
- NinjaTrackerPlus facts live in `docs/ninjatrackerplus.md`. MIDI Synth facts (the experimental aside: 7 voices, channel = instrument, file layouts) live in `docs/iigs-midisynth.md`. What each NTP build option gains and costs (fidelity, polyphony, file size) is in its "Build options: tradeoffs" section: update it when an option is added or re-measured. **Record every new MIDI Synth/synthLAB finding there, with its source.**
- Deferred plans (ideas to try later, with their background) live in `plans/`.
- Python: package `migs` in `src/migs/`, managed by uv (`pyproject.toml` + `uv.lock`). Entry points are listed in `[project.scripts]`. Add deps with `uv add`, never pip.
- Tests live in `tests/`. They use synthetic SCUMM/RO data so they run without the game. The real-game test skips when the data is absent. Add tests for every format rule you implement.
- Tools take input and output paths as arguments; no hard-coded game paths outside defaults.
- Never write into `original files/` (user-supplied: game data, MT-32 ROMs) or `ref/`.
- **Everything not under source control must be fetchable by `just setup`** (into gitignored `vendor/`, pinned versions and sha256 where available). The only exceptions are user-supplied files in `original files/`. When adding a dependency, add a `fetch-*` recipe for it, not manual steps.
- **Layout: tracked files are inputs, everything generated goes to `build/`.**
  - `config/`: hand-maintained settings (`instruments.toml`, `mt32bank.toml`, `ntp.toml`, optional `song_names.toml`, `emu/default-bram.hex`, `disk/README.TXT`: the NTP disk's root README, explaining the variant folders; keep it in step with them).
  - `original files/`: user-supplied game data and MT-32 ROMs. Only its README is tracked.
  - `build/`: all generated output, gitignored. That's `music/`, `ntp/<variant>/`, `seq/`, `disks/` (images plus the `.gs2` configs beside them), `dist/` (each disk as `<VOLUME>.zip` holding the image and `<VOLUME>.SHK`, a ShrinkIt archive of its files, made by `just disk` / `just synthlab-disk`), `cache/mt32samples/` and `looplab/`. `just clean` keeps `build/cache/`; `just clean-all` removes it all.
- Outputs must be reproducible from the game data plus `config/`. Byte-for-byte holds on one CPU architecture; known differences across platforms are accepted and listed here, not fixed:
  - **arm64 vs x86_64 floating point.** numpy's arm64 builds fuse multiply-adds (one rounding instead of two), so float results can differ in the last bit. One example: `audio.interp_at` matches `np.interp` exactly on x86_64 only. MODs built on Apple silicon may therefore differ from Linux x86_64 builds in a few sample bytes. That's inaudible, but not identical. Unmeasured: CI has no game data. Found in CI, 2026-11-11.
- `just` has no freshness tracking (every dependency recipe runs), so recipes skip themselves through `tools/fresh.py` (standard library only; usage in its docstring). `fresh get URL FILE SHA256` fetches a pinned download unless it's already there. `fresh run STAMP [--out PATH]... INPUT... -- CMD` runs CMD unless its inputs hash to the stamp, which is written only after success. It's used by `extract`, `fetch-munt`, `ntpmod` (one stamp per variant in `build/ntp/<mode>/.inputs`, inputs in the justfile's `ntp_inputs`) and `disk`. `py:FILE` inputs hash a module plus every `migs` module it imports, so new modules are picked up without editing the list. A new data file or tool that a build reads must be added to its inputs. `just ntpmod-force` rebuilds the NTP variants regardless.
- **Distribution:** never commit or publish `original files/` or `build/`. `build/` holds copyrighted derivatives of the game and ROMs: the extracted soundtrack, renders, NTP songs, sequences and disk images. Don't propose checking them in, even for CI.
- When a format fact is learned, record it in the matching `docs/*.md` file with its source.
